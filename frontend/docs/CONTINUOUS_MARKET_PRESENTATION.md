# 连续行情展示

2026-10-15，根据用户最新要求恢复持续可见的价格和长期历史，不改变首页主体布局、地图、研究内容和四价型语义。

## 两个独立合同

- `/api/market/display` 继续是严格 V2/V3 真实观测；校验、缺项、来源、城市和价型边界不变，V1 不接受。
- 首页使用 `/api/market/presentation` 的 `presentation-1` 整包。后端按今日真实观测、冻结模型计算、本地真实历史保底生成224个格子；计算证据、模型身份与校准输入留在后端。数据不会回写真实观测合同或模型输入。

## 初始数据与失败保护

`src/domain/market/publishedPresentation.json` 是发布器从实际数据库、历史和冻结模型输出生成的正式公开投影，具有相同 input_hash；不是测试 fixture，也不是旧 V1 比赛种子。

客户端启动先完整校验该正式投影，再建立60秒整包更新。请求失败、超时、无效 JSON、旧合同响应、空包、重复或缺格均不能替换有效发布。没有网络的第一次打开和重新加载仍能展示构建时的有效发布。日期保持发布中的实际值，页面刷新不会变成新的数据时间。

HTTP provider 默认构造仍支持严格 `/display`，供已有观测消费者使用；产品单例显式请求 `/presentation` 并要求原生版本。未来部署只需要更新 Runtime 发布，无须每次重建前端；正式构建投影只作为离线和接口失败时的可靠基底。

## 渲染与真实时间

`displayMarketFor` 在数据边界将记录投影为现有卡片类型，组件布局保持稳定。

- 当前卡片两位小数、元/kg、当前价型与“更新”日期保留；界面不展示计算/历史等内部来源种类。
- `display_date` 是实际观测日或计算日。`observed_at` 和 `collected_at` 只反映真实输入，允许null；不会以计算日冒充采集日。
- `history` 保留当前同源比较依据；计算行只有单个计算日，显示“最新”，不伪造涨跌。
- `trend_history` 单独保留同地区、商品、价型的真实长期源，最多128个实际点。长期曲线使用自身首尾日期和真实 `trend_sources` 链接，不把当日计算点拼入历史。
- 来源区域来自各记录真实URL，不从固定网站配置冒充具体观测。多来源均保留。

独立北京时间组件、地图、轮询及纸面状态继续分离。秒钟不会触发行情请求、重新计算整包、重放纸面动画或更新地图状态。

## 校验与运行

`marketPresentationSnapshot.ts` 校验224格唯一覆盖、有限正价、有效日期、历史末点、涨跌、来源URL、模型/价型面证据、长期序列身份；官方 V2/V3 原有校验不放宽。测试 fixture 只能在 `src/test/fixtures`，构建依赖扫描继续拒绝测试与旧 V1 资产。

运行 `npm run typecheck`、`npm test`、`npm run build`。发布命令和每日任务衔接见产品根 `pipelines/publishing/MARKET_PRESENTATION.md`。首次生成公开投影必须使用真实已验输入，不能手工填写价格或修改研究数据来通过验收。

没有对应冻结模型的作物使用数据库历史或由实际成对价格得到的价型面保底。尚无真实长期历史的格子不制造历史曲线，仍展示当前有效价格点。服务器定时任务是否启用需要部署阶段核实，本轮未连接服务器。
